# Semantic Gap และการค้นหาวิธีตามเงื่อนไข
ผู้ริเริ่มแนวคิด: Teeranat Butda  
สถานะ: หลักการและข้อเสนอการใช้งาน ไม่ใช่ผลพิสูจน์ว่าปัญหาทุกชนิดแก้ได้

## เมื่อไม่มีเส้นทางที่พร้อมใช้
คำอธิบายผู้ริเริ่ม วันที่ 5 พฤศจิกายน 2569:
> ถ้าคุณไปถึงแล้ว มันยังไม่เคยเห็นเส้นทางที่มีความหมาย ใช่ไหม ก็ไปถามเน็ต ถามเน็ตแล้วไม่มี ก็แค่ไปเชื่อมอยู่กับสิ่งที่มันใกล้ที่สุด แล้วก็หาความหมายระหว่างสองจุดนั้นมา

ใจความคืออย่าทิ้งเส้นทางและบริบทเดิมเมื่อพบช่องว่าง ให้เติมความรู้หรือสำรวจความสัมพันธ์ที่ขาด ณ จุดนั้น แล้วเดินต่อ การเชื่อมใหม่ยังต้องแยกสิ่งที่ค้นพบจริงออกจากสมมติฐาน

## ช่องว่างต่างชนิดต้องแก้ต่างกัน
- ขาดข้อมูล: ค้นแหล่งที่มีสิทธิใช้และตรวจต้นทาง
- ขาดความสัมพันธ์: เสนอ relation แล้วตรวจทิศทาง เงื่อนไขและหลักฐาน
- ขาดวิธีทำ: ค้น Method ที่รับ input และข้อจำกัดตรงโจทย์
- ขาดสิทธิ: ต้องแก้ที่ authorization ไม่ใช้คะแนนความใกล้กลบ
- ขาดการพิสูจน์: รันทดสอบหรือตัวตรวจอิสระ ไม่เติมคำอธิบายแทนผล

การแบ่งชนิดข้างต้นเป็นการสกัดเชิงออกแบบจากข้อเสนอ ไม่ใช่รายการ Canonical ใหม่

## คำตอบอาจเป็นวิธี ไม่ใช่ข้อเท็จจริงที่เก็บไว้
Research 1.0 หน้า 8 ใช้ตัวอย่างโจทย์คณิตศาสตร์เพื่ออธิบายว่า Method เป็นวัตถุความรู้ได้ โดยเก็บ preconditions, inputs, outputs, verifier, resource_budget และ evidence_of_performance

กระบวนการคือกำหนดเป้าหมายที่ตรวจได้ → บันทึกค่าที่ทราบและไม่ทราบ → ตัดวิธีที่ผิดเงื่อนไข → เลือกวิธีภายใต้งบ → ลงมือจริง → ตรวจผลอิสระ → เก็บผลการลอง

## ตัวอย่างและขอบเขต
การเก็บเงื่อนไข N = p × q ช่วยค้นวิธีที่เกี่ยวข้องและวางตัวตรวจได้ แต่ไม่เท่ากับคำนวณตัวประกอบสำเร็จ ความใกล้ของเวกเตอร์ไม่ได้พิสูจน์สมการหรือทำให้ความยากเชิงคำนวณหมดไป

เริ่มทดสอบจากตัวเลขขนาดเล็กที่รู้คำตอบ วัดแยกว่าระบบเลือกวิธีถูกหรือไม่ ตรวจ preconditions ถูกหรือไม่ และผลที่คำนวณจริงถูกหรือไม่

## ป้องกันการวนซ้ำ
เก็บว่าวิธีใดเคยลอง ภายใต้ input และเงื่อนไขรุ่นใด ผลเป็นอย่างไร การนำวิธีเดิมกลับมาใช้ควรมีเหตุผลว่าข้อมูลหรือเงื่อนไขเปลี่ยน ไม่วนเพียงเพราะลืมผลล้มเหลวเก่า
