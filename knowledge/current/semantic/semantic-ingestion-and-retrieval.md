# แยกการนำเข้าความรู้จากการค้นคืน
ผู้ริเริ่มแนวทาง Meaning Space: Teeranat Butda  
สถานะ: ข้อเสนอเชิงวิศวกรรมใน Research 1.0 ไม่ใช่คำรับรองติดตั้งระบบแล้ว

## เป้าหมาย
ไม่สร้างกราฟ ตีความ และตรวจทุกขั้นใหม่ทั้งหมดเมื่อมีคำถามทุกครั้ง งานที่ใช้ซ้ำควรทำตอนนำเข้า ส่วนงานตอบใช้เจตนาและบริบทปัจจุบันเลือกสิ่งที่เกี่ยวข้อง

## ทางนำเข้า
1. รับแหล่งที่มีสิทธิใช้ เก็บต้นฉบับ รุ่น วันที่ และขอบเขตการเข้าถึง
2. แยกข้อความ โมเดลเสนอ Sense, Entity, Event และ Relation พร้อมตำแหน่งข้อความที่รองรับ
3. ทำ embedding จากคำอธิบายความหมายร่วมบริบท พร้อม encoder_id, encoder_version, input_recipe, dimension และ source_hash
4. เชื่อมกับแนวคิดเดิมและตรวจชนิดข้อมูล ทิศทาง การปฏิเสธ หน่วย เวลา และข้อขัดแย้ง
5. จัดเก็บตามสถานะ แยกสิ่งที่โมเดลเสนอจากสิ่งที่ผ่านการตรวจ

source_hash ช่วยหลีกเลี่ยงการประมวลผลซ้ำเมื่อข้อมูลเดิมไม่เปลี่ยน แต่ hash ไม่บอกว่าข้อมูลนั้นจริง

## ทางตอบคำถาม
1. อ่านเจตนาล่าสุด เป้าหมาย ขอบเขต และเงื่อนไขสำเร็จ
2. กรองสิทธิและข้อจำกัดที่ห้ามละเมิด
3. ค้นผู้สมัครด้วย lexical retrieval และ embedding
4. เลือก Sense และเดิน relation ที่เกี่ยวข้องภายใต้งบเส้นทางและเวลา
5. คำนวณหรือเรียกโมเดลเท่าที่จำเป็น
6. ตรวจคำตอบกับหลักฐานและผูกผลกับ provenance

การพบข้อความใกล้กันไม่ใช่จุดจบ ต้องตรวจว่าตอบคำถามที่ถามจริงหรือไม่ ตัวอย่างยอดขาย “ดีขึ้น” ต้องระบุว่าจะวัดรายได้ กำไร หรือจำนวนลูกค้า และไม่เทียบเดือนที่ยังไม่ครบกับเดือนเต็มถ้าเจตนาห้ามไว้

## การลดภาระ
รายงานเสนอใช้ฐานข้อมูลเชิงสัมพันธ์เก็บรหัส ความสัมพันธ์ หลักฐาน และรุ่น แล้วเสริม vector index ตามความจำเป็น ไม่กำหนดว่าต้องใช้หลายบริการตั้งแต่เริ่ม

แคชต้องขึ้นกับข้อมูล รุ่นกฎ รุ่นโมเดล เจตนา และสิทธิ ไม่ใช้ผลแคชข้ามผู้ใช้โดยไม่ตรวจสิทธิ เมื่อเปลี่ยน encoder ให้สร้างดัชนีรุ่นใหม่ก่อนสลับใช้งาน ไม่เปรียบเทียบเวกเตอร์ต่าง encoder โดยไม่มีการปรับเทียบ

## การพิสูจน์ประโยชน์
เปรียบเทียบ BM25, embedding, hybrid, reranker และ graph-based retrieval ด้วยคลัง โมเดลตอบ และงบ context เดียวกัน ดูทั้งคุณภาพ หลักฐาน เวลา RAM และต้นทุน ไม่สรุปว่ากราฟดีกว่าเสมอ
