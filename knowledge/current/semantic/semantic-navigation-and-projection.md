# การนำทางความหมายและข้อจำกัดของภาพฉาย
ผู้ริเริ่มแนวคิด: Teeranat Butda  
สถานะ: หลักการเลือกมุมมองและข้อเสนอ UI เชิงข้อมูล

## วิธีคิดเป็นเข็มทิศ
ในบทสนทนาวันที่ 5 พฤศจิกายน 2569 ผู้ริเริ่มกล่าวถึงการซูมและการแพน แล้วระบุ:
> แต่เราก็ไม่ทิ้งสิบแปดวิธีคิด มันคือเข็มทิศในการเดินทางไปหาคำตอบ.

ตัวอย่างที่อธิบายคือการหาสูตรทอดไข่ หากหลงไปแก้โจทย์ด้านการสร้างบ้านหรือสร้างเตาก่อน ก็อาจได้เส้นทางที่ยาวเกินเจตนา แม้แต่ละขั้นมีความสัมพันธ์กัน การเกี่ยวข้องจึงยังไม่พอ ต้องเหมาะกับเป้าหมายและต้นทุนด้วย

## ความหมายของการซูม
Research 1.0 หน้า 7 อธิบาย:
- Zoom Out: มองหมวดหรือชุมชนความรู้ เช่น ธุรกิจ รายได้ กระแสเงินสด
- Zoom In: ลงไปที่ข้ออ้าง ตัวเลข และต้นฉบับหลักฐาน
- เดินเส้น: แสดงว่าใช้ relation ใดและข้อจำกัดใดในการเลือก

การซูมควรรักษาจุดอ้างอิงและเจตนาเดิม ทำให้ผู้ใช้ตรวจความสัมพันธ์จากภาพรวมลงสู่หลักฐานได้ ไม่ใช่เปลี่ยนโจทย์เมื่อเปลี่ยนมุม

## ภาพสองมิติไม่ใช่ความหมายทั้งหมด
ตำแหน่ง X/Y บนจอเป็น projection ของข้อมูลมิติสูง ระยะบนภาพอาจผิดจากระยะต้นฉบับ ภาพจึงเหมาะกับการมองและนำทาง แต่การตัดสินต้องใช้เวกเตอร์เต็ม relation และหลักฐานที่เกี่ยวข้อง

จำนวนมิติไม่ใช่จำนวนหลักทศนิยม เวกเตอร์ 384 มิติคือ 384 ค่า ไม่ใช่ความแม่นยำ 384 หลัก การเพิ่มมิติหรือทศนิยมไม่ได้รับรองว่าความหมายถูกต้องขึ้น

## ข้อกำหนด UI ที่สกัดได้
- บอกชัดว่าแผนภาพเป็นภาพฉาย
- เปิด Concept/Sense และหลักฐานจากวัตถุบนภาพได้
- แยกสีหรือป้ายของข้อเสนอ ข้อเท็จจริง ข้อขัดแย้ง และสิ่งที่ยังไม่ทราบ
- การเปลี่ยนมุมมองไม่ลบรหัสหรือประวัติของข้อมูล
- ไม่ใช้ความใกล้บนจอเป็นสิทธิอนุมัติการลงมือ

รายการ UI เป็นแนวทางประยุกต์ ไม่ใช่คำกล่าวว่าหน้าจอดังกล่าวสร้างและทดสอบแล้ว

## การตรวจ
ต้องตรวจได้ว่าซูมออก–กลับเข้าแล้วยังอ้างข้อมูลเดิม การเลือกเส้นที่ดูใกล้แต่ผิดทิศ/ผิดเวลาไม่ถูกนำไปสรุป และผู้ใช้เปิดที่มาของข้ออ้างได้แม้ภาพเปลี่ยน layout
