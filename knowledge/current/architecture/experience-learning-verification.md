# Experience Memory: จากการทำซ้ำสู่ความรู้ที่ตรวจและใช้ต่อได้

ผู้ริเริ่มโจทย์การเรียนรู้: Teeranat Butda  
เรียบเรียง: 8 พฤศจิกายน 2569  
สถานะ: สังเคราะห์แนวทางและเกณฑ์ทดลอง ไม่ใช่หลักฐานว่าระบบเรียนรู้ติดตั้งแล้ว

## การเก็บประสบการณ์ต้องทำให้งานครั้งถัดไปเปลี่ยน

เอกสารที่ผู้ใช้นำมาหารือวันที่ 22 ตุลาคมต้องการให้ระบบสะสมความรู้จากโมเดล เอกสาร เว็บ การสาธิต และผลการทำงานจริง แล้วนำกลับไปใช้ ไม่หยุดที่ตอบคำถาม ส่วนเอกสารปรับ Blueprint วันที่ 29 ตุลาคมแยก Experience Memory ออกจากการลองซ้ำสามรอบอย่างชัดเจน

การมี log จำนวนมากยังไม่แสดงว่าระบบเรียนรู้ ต้องตรวจว่าระบบดึงประสบการณ์ที่เกี่ยวข้องได้ นำไปใช้ภายใต้บริบทและสิทธิ์ปัจจุบัน และผลดีขึ้นจริงโดยไม่สร้างความผิดพลาดใหม่ การเรียนรู้ในบริบทนี้ไม่จำเป็นต้องหมายถึงการฝึกน้ำหนักโมเดลใหม่

## วงจรความรู้ในข้อกำหนดเดิม

Acquire → Interpret → Relate → Verify → Learn → Apply → Feedback

ความหมายคือรับข้อมูล ทำความเข้าใจ เชื่อมโยง ตรวจข้ออ้าง เก็บตามสถานะ นำไปใช้ แล้วประเมินผลย้อนกลับ แหล่งความรู้หนึ่งไม่ได้ถูกต้องโดยอัตโนมัติเพราะมาจากโมเดล และข้อมูลที่ยังไม่พิสูจน์อาจเก็บเพื่อศึกษาได้โดยต้องไม่ถูกนำเสนอเป็นความจริงที่ตรวจแล้ว

สถานะที่เอกสารเสนอ ได้แก่ Observed, Hypothesis, Tested, Verified และ Contradicted การเรียบเรียงนี้อ่านสถานะเหล่านี้เป็นการบอกฐานหลักฐาน ไม่ใช่บันไดที่ทุกข้อมูลต้องเลื่อนขึ้นทางเดียว ข้อมูลที่เคย verified ในขอบเขตหนึ่งอาจไม่ใช้ได้เมื่อบริบทเปลี่ยน

## หน่วยประสบการณ์ที่นำกลับมาใช้ได้

ข้อเสนอเชิงวิศวกรรมสำหรับจัดข้อมูล ไม่ใช่ schema ที่รับรองเพิ่ม:

- โจทย์และเงื่อนไขที่ทำให้ประสบการณ์นั้นเกี่ยวข้อง
- เจตนาและข้อจำกัดที่ต้องรักษา
- ขั้นตอนที่ทำและเครื่องมือที่ใช้
- ผลจริง หลักฐาน และรุ่นของ artifact
- ความล้มเหลวหรือสาเหตุที่พบ
- เงื่อนไขที่ห้ามนำเส้นทางเดิมไปใช้
- สิ่งที่เปลี่ยนหลังได้รับ feedback

Success Path เป็นส่วนหนึ่งของประสบการณ์ แต่การเก็บเฉพาะเส้นทางสำเร็จอาจทำให้ระบบเลือกวิธีเดิมซ้ำในบริบทที่เคยล้มเหลว จึงควรเก็บผลลบและขอบเขตการใช้ด้วย โดยถือเป็นข้อเสนอเพื่อให้เป้าหมายการเรียนรู้ตรวจได้

## Teach → Execute → Learn

กรณีสาธิตงานหนึ่งครั้งแล้วให้ระบบทำซ้ำ ต้องทดสอบทั้งกรณีหน้าจอเดิมและหน้าจอเปลี่ยนเล็กน้อย การบันทึกพิกัดคลิกแล้วเล่นซ้ำเป็นความสามารถ automation ส่วนการรู้ว่าควรใช้ขั้นตอนไหน เมื่อไรต้องหยุด และผลยังตรงเจตนาหรือไม่ เป็นอีกชุดความสามารถที่ต้องตรวจแยก

คำขอใหม่ยังต้องตรวจสิทธิ์ การเคยทำขั้นตอนหนึ่งสำเร็จไม่ให้สิทธิ์ทำซ้ำกับบัญชี ผู้รับ หรือข้อมูลใหม่โดยอัตโนมัติ

## การทดลองเพื่อแยกประโยชน์จริงออกจากความรู้สึก

ใช้โจทย์ที่เทียบกันได้ระหว่างไม่ใช้และใช้ memory วัดความถูกต้อง งานที่ทำสำเร็จ จำนวนการแก้ เวลารวม และผลผิดขอบเขต พร้อมแยกโจทย์ที่ใช้สร้างประสบการณ์ออกจากโจทย์ตรวจผล ไม่ควรนับการจำคำตอบเดิมบนชุดเดิมเป็นหลักฐานการปรับใช้ทั่วไป

ต้องมีกลไกบอกว่าประสบการณ์ใดหมดอายุหรือถูกหักล้าง แก้ด้วยบันทึกใหม่ที่เชื่อมกับของเดิม เพื่อรักษาที่มาและไม่ให้ข้อมูลเก่าถูกดึงกลับมาเป็นคำแนะนำปัจจุบัน

## ที่มาและสถานะปัจจุบัน

- “ตรวจสอบระบบ AIG Ultimate”, 22 ตุลาคม 2569: ผู้ใช้นำข้อกำหนดวงจรเรียนรู้ สถานะความรู้ และ Teach → Execute → Learn มาหารือ โดยเอกสารระบุเองว่าเป็นข้อกำหนด ไม่ใช่ยืนยันติดตั้งสำเร็จ
- “CANTI ติดตาม AIG”, 29 ตุลาคม 2569: เอกสารปรับ Blueprint ที่ผู้ใช้นำมาหารือแยก retry ออกจาก Experience Memory และใช้เพื่อปรับ ATI เดิม ไม่เริ่มโครงการใหม่
- เนื้อหานี้เก็บหลักการเรียนรู้ที่ใช้ต่อได้ ไม่รื้อฟื้นชื่อโครงการหรือค่าตั้งโมเดลในเอกสารเก่า

ยังไม่มีผลทดลองใหม่ในเอกสารนี้ จึงไม่อ้างว่าระบบเรียนรู้ได้ดีขึ้นตามตัวชี้วัดแล้ว
