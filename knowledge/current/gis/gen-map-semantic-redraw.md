# GEN MAP จากภาพดาวเทียมสู่แผนที่สังเขป

ผู้ริเริ่มข้อกำหนด: Teeranat Butda

สถานะ: ข้อกำหนดและบทเรียนจากการพัฒนา ไม่ใช่การรับรองความแม่นยำหรือผลทดสอบรุ่นปัจจุบัน

## ผลลัพธ์ที่ต้องรักษา

GEN MAP ต้องตีความสิ่งที่อยู่ในภาพก่อนสร้างลายเส้น ผู้ใช้ต้องการแผนที่สังเขปที่สื่อความหมายของน้ำ ถนน อาคาร แปลง และป่า ไม่ใช่เส้นขอบภาพที่ดูเรียบแต่จำแนกวัตถุผิด ข้อกำหนดวันที่ 26 กันยายน 2026 ระบุว่า “ให้เอไอ  วาดแผนที่สังเขปตามความหมายในภาพถ่ายดาวเทียม ให้เป็นลายเส่นวิศวกรรมแผนผังภูมิประเทศตามมาตรฐาน”

คำว่า “ตามมาตรฐาน” เป็นเป้าหมายของผู้ใช้ ยังต้องระบุมาตรฐาน สัญลักษณ์ ชั้นข้อมูล และเกณฑ์ตรวจที่ใช้จริง ไม่ถือว่าภาพขาวดำทุกภาพเป็นแบบวิศวกรรมที่รับรองแล้ว

## แยกผลผลิตสามชนิด

1. ภาพต้นฉบับพร้อมข้อมูลตำแหน่งและขอบเขต เป็นหลักฐานที่ต้องเก็บไว้
2. ภาพวาดใหม่แบบ image-to-image เป็นแผนที่สังเขปเพื่อให้มนุษย์ตรวจแก้ อาจสวยและสื่อความหมายดี แต่ยังเป็น raster
3. Geometry ที่แก้ไขได้ เป็นผล vectorization อีกขั้นหนึ่ง ต้องตรวจ topology ความครบถ้วน และตำแหน่งแยกจากความสวยของภาพ

บทเรียนเดือนสิงหาคมคือการพยายามแทนเป้าหมายภาพวาดใหม่ด้วย edge detection, segmentation และ smoothing ทำให้การพัฒนาเปลี่ยนโจทย์ การเลือกวิธีต้องสอดคล้องกับผลผลิตที่ขอ ถ้าต้องการทั้ง raster และ vector ให้สร้างลำดับงานสองขั้นอย่างชัดเจน

## ลำดับงานที่สกัดได้

- จับภาพพร้อม Bounds, Zoom และระบบอ้างอิงของแผนที่ เก็บต้นฉบับก่อนประมวลผล
- ใช้คำสั่งคงที่อธิบายประเภทวัตถุและรูปแบบลายเส้นที่ต้องการ พร้อมส่งภาพอ้างอิง
- รับภาพใหม่และเปิดเทียบกับต้นฉบับ ตรวจการคงตำแหน่ง รูปร่าง และความสัมพันธ์ระหว่างวัตถุ
- วางภาพคืนในขอบเขตเดิมเป็นชั้น AI Sketch โดยไม่แทนที่ข้อมูลสำรวจ
- เมื่อผู้ใช้ต้องการเส้นแก้ไขได้ ค่อยแยกชนิดวัตถุและสร้าง geometry แล้วตรวจซ้ำ

การใช้ Bounds เดิมเป็นเพียงการวางภาพกลับในพื้นที่เดิม ไม่พิสูจน์ว่าภายในภาพไม่มีการบิดเบือน โมเดลสร้างภาพอาจเพิ่ม ลบ หรือย้ายรายละเอียดได้ จึงต้องตรวจจุดอ้างอิงภายในภาพด้วย

## ขอบเขตความสามารถและการล้มเหลว

โมเดลที่เหมาะกับงานภาพดาวเทียมอาจไม่พร้อมรันบน browser มือถือ ต้องตรวจ runtime รูปแบบโมเดล หน่วยความจำ และเวลาประมวลผลก่อนเลือก เมื่อใช้บริการ AI ผ่าน backend ให้เก็บ credential ฝั่ง server ไม่ฝังลง HTML

เมื่อประมวลผลไม่ได้ ให้รายงานข้อผิดพลาดตรงขั้น ไม่เปลี่ยนเป็นวิธีอื่นที่ให้ผลคนละประเภทโดยเงียบ ๆ การตรวจ syntax ผ่านไม่ได้ยืนยันคุณภาพการตีความหรือความถูกต้องเชิงตำแหน่ง

## เกณฑ์ตรวจที่เสนอสำหรับการนำไปใช้

ข้อเสนอต่อไปนี้เป็นการสังเคราะห์เพื่อทดสอบ ไม่ใช่ผลผ่านแล้ว: ตรวจแม่น้ำและถนนว่าต่อเนื่องถูกต้อง อาคารไม่รวมเป็นก้อนเดียว ประเภทวัตถุไม่สลับ ตรวจรายละเอียดเล็กและส่วนที่หาย ทดสอบการวางกลับหลัง pan/zoom และเก็บผลก่อนกับหลังเพื่อให้ย้อนตรวจได้

## ที่มาและความไม่แน่นอน

- “ค้างไฟล์ BigMap”, 8 สิงหาคม 2026: อ่านข้อความผู้ใช้และคำอธิบายการเปลี่ยนจาก segmentation ไป image-to-image โดยตรง ภาพแนบบางส่วนไม่ปรากฏในข้อความที่เข้าถึง จึงไม่รับรองคุณภาพภาพที่กล่าวถึง
- “ตอบรับความไหล”, 26 กันยายน 2026: ข้อกำหนดแผนที่สังเขปและคำสั่งให้นำขั้นนี้ไว้ช่วงต้นของงาน
- ไม่ได้นำข้อมูลพื้นที่จริง ภาพต้นฉบับ หรือค่าพิกัดมาเผยแพร่
