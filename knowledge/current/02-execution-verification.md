# แยกการคิด การลงมือ และการตรวจ
ผู้ริเริ่มกรอบ: Teeranat Butda
สถานะ: สรุปเอกสารที่ผู้ใช้นำมาหารือวันที่ 29 ตุลาคม 2569 ไม่ใช่หลักฐานติดตั้งหรือการรับรองว่าเป็น Canonical ใหม่

## ความรับผิดชอบ
ATI รับเจตนา วางแผน ควบคุม และตีความ ส่วน AIG เป็นชั้นลงมือทำ โดย ASI ถูกเสนอให้คงเป็น Alias แทนการสร้างอีกระบบหนึ่ง

ชั้นลงมือทำควรรับรู้หน้าจอและ DOM ได้เพื่อทำงานตามแผน แต่ไม่มีสิทธิ์เปลี่ยนเป้าหมายเอง หลักในเอกสารคือ Goal-Blind but Action-Aware

## การตรวจสามระดับ
1. Schema Guard ตรวจรูปแบบและสัญญาข้อมูล
2. Semantic Verifier ตรวจความหมายและความตรงกับเจตนา
3. Domain Verifier ตรวจผลเฉพาะงาน เช่น พิกัด มาตราส่วน และการเปิดไฟล์ CAD จริง

JSON Schema ที่ผ่านไม่ใช่หลักฐานว่าความหมายถูกต้อง การใช้ตัวตรวจเดียวแทนการตรวจโดเมนอาจพลาดผลลัพธ์ที่มีรูปแบบถูกแต่ใช้งานจริงผิด

## การเรียนรู้และ Root Re-entry
การลองใหม่อย่างเดียวไม่ใช่หลักฐานการเรียนรู้ เอกสารเสนอ Experience Memory เพื่อเก็บเส้นทางสำเร็จแล้วเรียกใช้เมื่อบริบทเหมาะสม การส่งกลับแก้ไขต้องรักษาเจตนาและมีหลักฐานว่าข้อผิดพลาดถูกแก้

ค่า Loop ไม่เกิน 3 ปรากฏในเอกสารรุ่นนี้ แต่ไม่ควรนำไปประกาศเป็นข้อจำกัดสากลของทุกสถาปัตยกรรมโดยไม่เทียบข้อกำหนดล่าสุดของโครงการนั้น

## ขอบเขต
ใช้เป็นเกณฑ์ตรวจระบบเดิม ไม่ถือเป็นคำสั่งเริ่ม ATI/AIG โครงการใหม่ และไม่เปลี่ยนสถานะ Archive ของ AIG เดิม
